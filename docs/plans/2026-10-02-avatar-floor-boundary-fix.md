# 解決人偶掉落至螢幕下方/畫面外與邊界約束實作計畫 (Implementation Plan)

## 1. 問題根本原因分析 (Root Cause Analysis)

### 1.1 為什麼會「掉到螢幕下」（下半身沉入工作列下方）？
- **相機預設為半身特寫視角**：
  在 `SceneManager.js` 中，相機預設距離為 `1.8m`，視線中心高達 `targetPanY = 1.25m`（半身/胸口特寫模式）。
- **地板座標與視錐下界錯位**：
  物理引擎的地板固定在 3D 空間 `floorY = 0.0`。在半身視角下，相機視錐（Frustum）的垂直可見範圍僅為 `0.96m`，畫面底部對應的 3D 高度為 `1.25 - 0.48 = 0.77m`。
  因此，當人偶掉落或站在 `floorY = 0.0` 時，她的腰部剛好卡在畫面底部，雙腿與雙腳落在 `0.77m` 以下（完全沉入 Windows 工作列下方且不可見），如截圖所示。

### 1.2 為什麼會「掉到螢幕外」（左右飛出邊界）？
- **墜落階段缺乏水平邊界約束**：
  在 `MascotPhysicsController.js` 的 `slot.physicsState === 'falling'` 狀態中，只做了 Y 軸重力加速度與地面碰撞檢測，完全沒有對 X 軸水平飛行做 `minX / maxX` 邊界限制。
- 當使用者朝左右拋擲、或人偶在邊界附近墜落時，水平慣性速度會直接將人偶帶出視窗或螢幕邊界之外。

---

## 2. 解決方案 (Proposed Solution)

### 修正 1：全螢幕/桌面漫遊模式預設與自適應「全身立足視角（Full-Body View）」
- 在 `SceneManager.js` 中優化全螢幕畫布下的相機預設：
  - 進入全螢幕透明畫布時，自動調校相機參數為全身視角：`targetCameraDist = 3.3m`、`targetPanY = 0.72m`。
  - 確保畫面底部恰好落在 `Y = -0.15m` 處，讓小櫻腳底踩著的 `floorY = 0.0` 平穩懸浮於 Windows 工作列上緣上方約 30~50px，整座身體（頭頂到腳底鞋跟）完整清晰可見。

### 修正 2：墜落與拋擲增加左右螢幕邊界彈性碰撞（Wall Bounce）
- 在 `MascotPhysicsController.js` 的 `falling` 物理循環中加入水平邊界檢查：
  - 當人偶橫向掉落碰到左側螢幕邊界或右側螢幕邊界時，自動反彈（`slot.velocity.x *= -0.5`）並將座標限制在螢幕內，**絕對不會飛出螢幕外**。

### 修正 3：工具列與對話框安全邊界調整（避開 Windows 工作列）
- 全螢幕透明模式下，工具列底距由 `bottom-6` 調整至 `bottom-12`（約 48px），避免被 2560x1600 高解析螢幕下方的 Windows 工作列遮蔽。
